/tg/ Station 13 - Modules - Types — Var Details - Proc Details

tts
/datum/controller/subsystem/tts

Vars

admin_enabledAdmin-controlled gate for new TTS requests. Backend connectivity remains in tts_enabled.
available_speakersA list of available speakers, which are string identifiers of the TTS voices that can be used to generate TTS messages.
average_tts_messages_timeUsed to calculate the average time it takes for a tts message to be received from the http server For tts messages which time out, it won't keep tracking the tts message and will just assume that the message took 7 seconds (or whatever the value of message_timeout is) to receive back a response.
completed_tts_messagesTTS requests for radio TTS audio playback. Cleared when it's been in here for 30 seconds. list("identifier" = list("ref" = [ref], "expiry_time" = world.time))
computer_voiceUsed as the Computer voice, to keep narration the same across computers.
current_processing_http_messagesHTTP requests that are being processed to see if they've been finished
current_processing_tts_messagesTTS audio files that are being processed on when to be played.
custom_voice_ownersApproved player-made voice ID -> owner ckey.
custom_voices_enabledWhether the TTS server supports player-made voices.
in_process_http_messagesHTTP requests currently in progress but not being processed yet
instruction_enabledWhether the TTS server accepts natural-language voice instructions.
max_concurrent_requestsThe max concurrent http requests that can be made at one time. Used to prevent 1 server from overloading the tts server
message_timeoutTTS messages won't play if requests took longer than this duration of time.
pitch_enabledWhether the TTS engine supports pitch adjustment or not.
queued_http_messagesQueued HTTP requests that have yet to be sent. TTS requests are handled as lists rather than datums.
queued_radio_messagesTTS requests for radios who heard a TTS message. list("identifier" = list("radio" = [ref], "hearers" = list([hearer_ref], ...)))
queued_radio_messages_compressionList of radio TTS messages with compression, used for fixing radio TTS during ionosphere storms to conceal text.
queued_tts_messagesAn associative list of mobs mapped to a list of their own /datum/tts_request_target
random_voicesVoice IDs suitable for random assignment: adult voices that speak the server's language.
rate_enabledWhether the TTS server accepts a speaking rate.
supported_soundsNonverbal tags the TTS server accepts as sound.
supported_stylesControl tags the TTS server accepts as style.
tram_voiceUsed as the Tram voice, to keep narration the same across tram devices.
tts_enabledWhether TTS is enabled or not
voice_aliasesRetired voice ID -> the voice that replaced it, so saved characters keep a voice.
voice_info_loadedWhether voice metadata has been loaded from the server or the cache.
voice_labelsVoice ID -> readable label shown in the preferences menu.

Procs

apply_voice_infoReplaces the voice metadata. Returns FALSE and clears it if info is malformed.
can_use_custom_voiceWhether user may speak with the player-made voice voice: it must be theirs and they must be a donor.
custom_voice_callCalls the TTS server's custom voice API and waits for the answer. This is blocking. Returns list(status code, decoded JSON body or null, error message or null).
ensure_voice_infoLoads cached voice metadata, for preferences built before the server answers.
establish_connection_to_ttsEstablishes (or re-establishes) a connection to the TTS server and updates the list of available speakers. This is blocking, so be careful when calling.
is_custom_voiceWhether voice is an approved player-made voice.
is_runtime_enabledReturns whether new TTS audio requests are currently accepted.
load_voice_infoFetches the optional voice metadata. Servers without it only lose the extras. This is blocking, so be careful when calling.
random_tts_voiceHelper to get a random TTS voice for a certain gender. Passing no gender just results in a random voice.
refresh_custom_voicesReloads which player-made voices may speak, and who owns them. This is blocking.
refresh_voice_preferencesRebuilds everything derived from the voice list once the TTS server has answered. Preferences read earlier, while the world was still starting, only had the previous round's cached list; after a voice list change that list rejects every saved voice.
resolve_voiceMaps a voice ID saved before a voice list change onto the voice that replaced it.
set_admin_enabledChanges the runtime TTS gate, reconnecting the configured backend when needed.
station_voice_catalogBuild the directory only on a full update of the device page, and send machines for one area.
voice_display_namesMaps each preference choice to a readable label, or returns null when the server provides none. Choices without a label, such as "None", keep their own text.
voice_list_is_liveWhether a saved voice can be checked against the voice list yet. Before the TTS server answers, the list is the previous round's cache and may predate a voice list change.
